# Astro Semantic Component Builder Skill

This skill guides the agent through technical implementation standards for translating an approved content wireframe into an isolated, ultra-lightweight Astro component file.

## When to use this skill

- Use this skill immediately after the user provides explicit approval on an SEO content plan generated by the `seo-copywriting` skill.
- Use this when modifying, refactoring, or optimizing any existing `.astro` component within the codebase.

## How to use it

You must scaffold and write the component following the architectural restrictions below, leveraging Astro v6.3.7 features natively.

### 1. File Structure & Component Separation
Every component must follow the traditional Astro three-part anatomy:
- **Component Script (`---`):** Keep it clean. Import local components or assets, and define local variables or content matrices here. Ensure any static data arrays used for looping (`.map()`) are declared inside this block to separate logic from presentation.
- **Component Template:** Write pure, semantic HTML. Consume the frontmatter variables. Never include layout wrappers that don't add semantic value.
- **Component Style (`<style>`):** Write native vanilla CSS. Astro v6.3.7 automatically scopes these styles to the component, minifies them, and optimizes delivery.

### 2. Strict Asset & Media Handling (Astro v6.3.7 Standard)
To maintain a perfect Lighthouse score, asset delivery must be flawless:
- **Images:** You MUST import the native `Image` component via `import { Image } from 'astro:assets';`.
- Always provide absolute dimensions (`width` and `height`) and descriptive `alt` text.
- Follow the loading strategy enforced in `@/.agents/rules/lighthouse-core-vitals.md` to protect the Largest Contentful Paint (LCP).
- **Icons:** Inline optimized SVG code directly within the template or load them via local static components. Avoid external icon fonts or heavy JS bundles.

### 3. Cross-Referencing Constraints
While building, you must actively comply with the project's active rules:
- **Semantic Integrity:** Check against `@/.agents/rules/semantic-html-writing.md`. If you find yourself typing a structural `<div>`, halt and substitute it with a semantic landmark (`<section>`, `<article>`, etc.).
- **Code Quality:** Check against `@/.agents/rules/clean-code-conventions.md`. Keep CSS selectors flat, avoid deeply nested structures, and use meaningful kebab-case class names.

## Implementation Example Template

When generating a component, ensure its architectural backbone mirrors this layout:

```astro
---
import { Image } from 'astro:assets';
import myAsset from '../assets/hero-bg.jpg';

// Content Matrix for clean template rendering
const features = [
  { title: 'Semantic Pureness', body: 'Zero un-semantic structural tags.' },
  { title: 'Lighthouse Driven', body: 'Engineered for core web vitals.' }
];
---

<section class="features-module">
  <header class="features-header">
    <h2 class="features-title">Engineered for Performance</h2>
    <p class="features-subtitle">Pure Astro implementation.</p>
  </header>

  <ul class="features-grid">
    {features.map((item) => (
      <li class="features-grid-item">
        <article class="feature-card">
          <h3 class="card-title">{item.title}</h3>
          <p class="card-body">{item.body}</p>
        </article>
      </li>
    ))}
  </ul>
</section>
```
